# Workflow de Interface Web

Sequência de etapas que [[wiki/entities/nasser|Násser]] usa para levar uma interface web da ideia ao código ([[wiki/sources/interfaces-web-introducao-workflow-grids-pagemap-wireframes-style-guide]]):

| Etapa | Itens do slide | Onde |
|---|---|---|
| 1. Pesquisa | Briefing, documentação, referências | antes de desenhar |
| 2. [[wiki/concepts/wireframe\|Wireframes]] | Esboço, prototipação, grids | [[wiki/entities/figma]] |
| 3. Protótipo final UI | [[wiki/concepts/style-guide\|StyleGuide]], aplicar cores, layout | Figma |
| 4. Codificação front-end | HTML, CSS, JS; responsividade; testes | código |
| 5. Motion design | HTML, CSS, JS; responsividade; testes | código |

O módulo de interfaces web cobre as três primeiras. A pesquisa é "o embrião de uma interface web": saber "o que tem que ter de informação" antes de projetar. Os wireframes são "protótipos de baixa fidelidade" que permitem "projetar de maneira simples". O protótipo final aplica o style guide e as cores, "maior fidelidade na prototipagem". Dentro dos wireframes, o [[wiki/concepts/pagemap]] vem primeiro.

A fidelidade cresce a cada etapa: estrutura primeiro, visual depois.

`[skill: ux-ui-mentor]` A skill descreve o mesmo espectro (sketch → wireframe → mockup → protótipo → MVP) com a regra "use a menor fidelidade que ainda responda sua pergunta". Ela também alerta contra pular do wireframe para a alta fidelidade sem testar a estrutura. No slide, "Testes" aparece só nas etapas de código.
