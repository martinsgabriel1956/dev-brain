# Mentalidade de Crescimento (Carreira Dev)

## TL;DR

Segundo [[wiki/entities/andre-casciotti]], "nada é definitivo" na carreira: um dev experiente em Java pode migrar para dados/Python, ou um dev C# pode virar analista de dados, sem que a escolha inicial seja uma prisão. A barreira para aprender uma **nova** linguagem cai muito depois de já se dominar uma primeira — o que torna mudanças de rumo mais baratas conforme a carreira avança, ao contrário da crença de que "trocar depois de anos" é mais arriscado.

## A recomendação prática

Mesmo sem intenção de trocar de carreira, o autor recomenda que devs plenos/sêniors que nunca saíram do próprio paradigma experimentem outro:

- Java → **Clojure** (funcional, mas de sintaxe/ecossistema mais próximos da JVM, logo menor barreira) ou Scala
- C# → **F#** (funcional, dentro do mesmo runtime .NET)

O objetivo não é a troca de linguagem em si, mas o contato com um **paradigma diferente** — isso muda a forma de enxergar problemas mesmo em código que continua sendo escrito na linguagem original.

## Por que isso resolve um problema de [[wiki/concepts/escolha-rapida-de-caminho-de-carreira]]

A recomendação de "escolher rápido" no início da carreira só é segura se a escolha não for vista como permanente — sem mentalidade de crescimento, "escolher rápido" soaria como uma aposta de alto risco. Os dois conceitos se sustentam mutuamente: escolha rápido porque nada é definitivo, e nada precisa ser definitivo porque a segunda escolha (e a terceira) fica cada vez mais barata.
