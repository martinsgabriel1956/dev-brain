# Estrutura de README

Para quem ainda não tem site, o README no [[wiki/entities/github|GitHub]] é o portfólio: "a forma de como você apresenta o projeto diz muito sobre o que você aprendeu sobre o projeto, então a sua experiência meio que já está catalogada aqui no README" ([[wiki/sources/frontpush-monetizacao-freelancer-como-construir-um-portfolio]]).

## Seções que se repetem nos exemplos da aula

1. Imagem ou GIF do projeto.
2. Título e descrição curta (o que é e por quê).
3. Características ou funcionalidades.
4. Tecnologias, cada uma com link.
5. Pré-requisitos ("você precisa do Git").
6. Passo a passo para instalar, configurar a database e rodar (Yarn ou npm).
7. Screenshots e link do deploy (por exemplo na [[wiki/entities/vercel|Vercel]]).
8. Roadmap ou metodologia, contribuição, licença, autor e contato.

"Uma descrição sucinta, não foi muita coisa e é uma boa descrição."

## Por que importa

- É onde fica a narrativa do projeto que o júnior conta na entrevista ([[wiki/concepts/demonstrar-experiencia-na-primeira-vaga]]).
- `[skill: tech-mentor-leadership]` Do lado do time, um README bom tem "setup em ≤ 5 comandos" e passa no teste de um novato seguir à risca (`onboarding-tecnico.md`). O mesmo teste serve para o README de portfólio.
