# Sustentação de software como receita recorrente

Modelo 2 de [[wiki/concepts/modelos-de-cobranca-de-servicos-de-ia]], segundo [[wiki/sources/5-modelos-economicos-para-vender-servicos-de-ia-ronald-hulk]]: projeto grande ([[wiki/concepts/venda-por-projeto-de-ia]]) + **mensalidade menor** pela sustentação. Sustentação = **suporte, manutenção e disponibilidade**; **não** inclui features novas (essas viram novo contrato). O software continua do cliente.

Caso do autor: escritório de advocacia que queria um RAG tradicional — back end + front end simples, e o cliente paga para manter no ar, pois não tem time para isso. Vantagens: caixa recorrente; a sustentação pode ser delegada a alguém contratado (mesmo no zero a zero, mantém a porta aberta); a feature nova entra com lucro líquido.

**Risco central:** com 3–4 clientes, sustentação que consome muito tempo impede aprender, evoluir e pensar no negócio — por isso o autor defende tirar a sustentação do próprio ombro quando der. Relaciona-se a [[wiki/concepts/recorrencia-em-servicos-de-ia]].
