# Escolher o Projeto Antes da Tecnologia

Estratégia para começar a aprender a programar: ao invés de decidir primeiro qual linguagem, framework ou editor usar, a primeira decisão deveria ser um projeto real — uma página web ou funcionalidade simples que pessoas de fato poderiam usar — escolhido puramente pelo critério de gerar adrenalina (interesse genuíno) em quem vai construí-lo. A tecnologia é escolhida depois, em função do projeto.

## Por que a ordem importa

Perguntar "por onde eu começo?" e responder primeiro com uma tecnologia tende a gerar aprendizado sem direção real — a pessoa aprende sintaxe sem ter um motivo concreto para aplicá-la. Escolher o projeto primeiro dá à tecnologia um propósito imediato: aprende-se o que é necessário para aquele projeto específico, não um currículo genérico.

## Não importa a linguagem, importa o brilho nos olhos

Linguagem de programação (JavaScript, PHP, C#, Java) e editor de código (VS Code, Vim) são descritos como escolhas irrelevantes nessa fase inicial — o que importa é usar o que gera mais interesse genuíno. Cursos e aprofundamento técnico vêm depois, quando a pessoa já sabe, na prática, o que quer construir.

## Aplicação como estratégia de portfólio

O mesmo princípio se estende à busca por emprego: implementar sozinho uma única funcionalidade do sistema de uma empresa-alvo — ou uma tela específica, no caso de front-end — e anexar o link no momento de se candidatar. Ver [[wiki/concepts/portfolio-backend-junior]] para o checklist mais amplo do que diferencia um portfólio júnior.

O peso de uma única pessoa implementar sozinha algo que normalmente é trabalho de um time inteiro é descrito como desproporcionalmente alto do ponto de vista de quem recruta — não porque times sejam ineficientes por natureza, mas porque a complexidade de comunicação cresce mais rápido que a velocidade de entrega à medida que mais pessoas entram no processo.

## Relação com outros conceitos

- [[wiki/concepts/dopamina-e-projetos]] — tensão a observar: escolher pelo critério de "adrenalina"/interesse genuíno pode ser o mesmo mecanismo de dopamina de antecipação que leva a abandonar projetos na fase de construção; a diferença proposta aqui é que a adrenalina serve para *escolher* o projeto, não para sustentar sozinha a execução dele
- [[wiki/concepts/maximizar-pontos-fortes]] — princípio irmão: impacto e propósito real antes de habilidade técnica isolada
- [[wiki/concepts/checklist-primeiro-dia-projeto]] — depois de escolhido o projeto, esse checklist cobre a ordem tática de setup
- [[wiki/concepts/projetos-fundamentais-para-aprender-a-programar]] — tensão de fase: aquele conceito prescreve três projetos específicos por habilidade (estado, modelagem, algoritmos), enquanto este recomenda escolher pelo interesse genuíno do aprendiz; não são contraditórios, respondem perguntas diferentes

Tensão de escala com [[wiki/concepts/projeto-impossivel]]: ambos recomendam um projeto único e de longo prazo em vez de vários pequenos, mas por critérios diferentes — este conceito prescreve escolher pelo interesse genuíno de quem aprende (fase inicial), enquanto o projeto impossível prescreve escala deliberadamente maior que a capacidade atual, especificamente para caber conceitos de arquitetura distribuída que não cabem num projeto pequeno mesmo que interessante.
