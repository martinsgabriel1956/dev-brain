# Onboarding de Codebase

Processo estruturado de absorção de uma codebase existente — seja como novo dev no time, desenvolvedor mudando de equipe ou contribuidor open source. Distinto de [[wiki/concepts/onboarding]] de empresa: o foco é exclusivamente no código, na arquitetura e no domínio do produto.

## Método iterativo (10 etapas)

1. **Leia a documentação** como primer cognitivo — não para entender tudo, mas para ter uma primeira impressão que acelera os "aha moments" depois
2. **Use o software como usuário final** — contexto de uso torna o código mais legível
3. **Explore com intenção** ([[wiki/concepts/exploracao-com-intencao]]) — siga o fio de uma feature real, não browse aleatoriamente
4. **Complete tarefas que toquem o core** ([[wiki/concepts/good-first-issue]]) — contribuição real enquanto aprende
5. **Escreva testes** ([[wiki/concepts/testes-como-aprendizado]]) — forçar compreensão do comportamento esperado
6. **Pair programming** ([[wiki/concepts/pair-programming]]) — observe antes de participar
7. **Anote e ensine** ([[wiki/concepts/aprender-ensinando]]) — expõe gaps de compreensão
8. **Entenda o domínio** ([[wiki/concepts/entendimento-de-dominio]]) — conecta decisões técnicas ao negócio
9. **Repita o ciclo** ([[wiki/concepts/ciclo-de-revisita]]) — cada volta traz mais profundidade
10. **Contribua com a documentação** — facilita o próximo dev no mesmo caminho

## Por que múltiplas impressões

Cada exposição ao mesmo conceito no código aprofunda a compreensão. Ver a documentação, usar o app, ler o código e escrever testes sobre o mesmo fluxo é [[wiki/concepts/aprendizado-por-impressoes]] em ação — não redundância, mas consolidação.

## Estado-alvo

Quando você usa o app e consegue visualizar mentalmente qual código está rodando por baixo, o onboarding está completo no nível prático. O entendimento arquitetural mais profundo continua se acumulando por meses.
