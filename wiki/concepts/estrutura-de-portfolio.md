# Estrutura de portfólio

Para [[wiki/entities/nasser|Násser]], os portfólios bons de dev e de design repetem a mesma ordem, e "não tem muito o que ensaiar nisso tudo" ([[wiki/sources/frontpush-monetizacao-freelancer-como-construir-um-portfolio]]):

1. **Capa (o envelope):** nome, uma ou duas skills, uma frase sobre o que faz e onde mora. Serve só para "incitar" a pessoa a abrir: "o que realmente interessa não é essa primeira seção".
2. **Trabalhos:** poucos e diversos, cada um com objetivo próprio (landing page, projeto de animação, SPA com [[wiki/concepts/crud|CRUD]], site institucional), explicado "de forma concisa e coerente".
3. **Sobre:** cursos, graduação, história, para "dar uma humanizada", porque "pessoas contratam pessoas". Designers somam depoimentos e empresas atendidas.
4. **Contato:** e-mail, LinkedIn, GitHub ou Dribbble, e o CV ([[wiki/concepts/estrutura-de-curriculo]]).

O passo seguinte é uma página por projeto com cliente, objetivos, descrição e tecnologias. Para quem começa, o README no GitHub já cumpre esse papel ([[wiki/concepts/estrutura-de-readme]]).

## Critérios

- **Direto e claro:** "muitas dobras, muita coisa" tiram a objetividade; é reduzir a [[wiki/concepts/carga-cognitiva]] de quem avalia.
- **Título enxuto:** duas skills só com carreira longa; o júnior escolhe uma ([[wiki/concepts/posicionamento-no-mercado]]).
- **Site próprio é opcional:** "necessário, necessário não é, mas é bom"; pesa mais para design e para freela ([[wiki/concepts/branding-pessoal]]).
- **Não existe sem trabalho:** sem projetos e sem a [[wiki/concepts/metodologia-e-clareza|metodologia]] por trás, não há o que pôr nele.
