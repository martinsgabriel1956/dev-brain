# Contribuir com Open Source

Contribuir com projetos open source que você já usa no dia a dia é apontado como recurso de aprendizado prático — mais efetivo do que contribuir com um projeto aleatório, porque você já entende o valor e os problemas reais da ferramenta.

## Duas formas de aplicar

1. **Contribuir diretamente:** procurar issues marcadas `good first issue` ou `good first fix` no GitHub como ponto de entrada — ver [[wiki/concepts/good-first-issue]].
2. **Inspirar-se para criar o próprio projeto:** usar a estrutura de um projeto open source existente como referência para construir algo próprio (exemplo citado: um "roadmap de investimentos" inspirado na estrutura do [[wiki/concepts/roadmap-sh]]).

## Caso: API TibiaData e o Custo Não Remunerado do Open Source

[[wiki/sources/aprenda-a-programar-do-jeito-dificil]] traz o caso da API TibiaData, mantida sem cobrança e sem rate limit por seu dono, recebendo mais de 1 bilhão de requests por mês — custo mensal pago do próprio bolso do mantenedor. O autor da fonte, contribuidor da API, relata ter gasto "horas e mais horas" sem remuneração direta, mas atribui suas contribuições a essa API como um dos principais motivos para conseguir o primeiro emprego como desenvolvedor Go. Reforça o padrão desta página: contribuir com uma ferramenta que você já usa e entende gera valor de carreira mesmo sem retorno financeiro imediato do próprio ato de contribuir.
