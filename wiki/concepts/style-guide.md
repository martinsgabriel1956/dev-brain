# Style Guide

"Meio que um guia para poder ter consistência no meu design", montado quando o projeto caminha para o protótipo final, "onde eu literalmente vou aplicar as cores e padrões com mais teor de fidelidade" ([[wiki/sources/interfaces-web-introducao-workflow-grids-pagemap-wireframes-style-guide]]). Ele reúne as regras dos módulos anteriores numa referência só. É a terceira etapa do [[wiki/concepts/workflow-de-interface-web]].

Conteúdo do style guide do case [[wiki/entities/nubank]]:

- branding e cor, com o porquê de cada cor;
- [[wiki/concepts/tipografia]] no desktop e no mobile, "para poder garantir acessibilidade e legibilidade";
- [[wiki/concepts/botoes-em-interfaces|botões]], inputs, [[wiki/concepts/grid-de-colunas|grids]], [[wiki/concepts/icones-em-interfaces|ícones]], cards, mockups.

Na aula prática de botões, o hover com [[wiki/concepts/sombra-em-interfaces|sombra]] e os padrões de tamanho de texto ficam para ser documentados no style guide ([[wiki/sources/botoes-pratica-figma-padding-gradiente-contraste-smooth-shadow]]).

`[skill: ux-ui-mentor]` Um design system tem camadas: tokens → componentes base → componentes compostos → patterns → guidelines, e é um acordo entre design e dev. O style guide da aula cobre a parte visual (os valores e os componentes desenhados) num arquivo do [[wiki/entities/figma]]. Para virar design system faltam nomes de token, estados de cada componente (hover, focus, disabled, loading) e regras de uso.
