# Page Map

A lista em ordem das seções (as "dobras") de uma página e do que cada uma leva, feita antes de desenhar o [[wiki/concepts/wireframe]]. O curso do [[wiki/entities/frontpush|FrontPUSH]] escreve o termo de várias formas: "page map", "pagemap" e "PageMap". As aulas o definem assim:

- O "flow das dobras, das seções": a ordem em que cada seção aparece "a cada seção que eu vou descendo no meu site". [[wiki/entities/nasser|Násser]] chama as dobras de "minhas telinhas". O page map nasce "um pouco antes do wireframes" e acompanha o wireframe desde a baixa fidelidade ([[wiki/sources/wireframes-parte-1-o-que-e-uso-foco-page-map-papel-e-caneta]]).
- Ele monta o page map "para poder me guiar e depois construir os wireframes que condizem com esse page map"; o slide diz "Construir o flow, o pagemap" ([[wiki/sources/wireframes-parte-2-briefing-objetivo-page-map-leitura-f-z]]).
- O page map "vai estabelecer o mapa, meio que o flow, o fluir de como vai se dar o passo a passo das seções do seu site" ([[wiki/sources/wireframes-parte-3-passo-a-passo-fidelidade-escala-de-cinza-segredo]]). Essa página o descreve como o mapa das seções "de uma página ou site", enquanto as outras falam de uma página só.
- O "flow de seções, de dobras" de uma página, decidido antes dos wireframes ([[wiki/sources/interfaces-web-introducao-workflow-grids-pagemap-wireframes-style-guide]]).
- A aula prática 1 (aula 08) não o define: diz que foi "trabalhado demais" nas aulas anteriores e o usa como base do "Frankenstein" ([[wiki/sources/wireframes-pratica-1-hero-page-map-frankenstein-referencias]]). Na página dessa fonte, a definição era inferida do uso; as outras aulas confirmam a mesma ideia.

"Dobra" é cada faixa vertical da página, a começar pela que aparece sem rolar. A primeira costuma ser o hero ([[wiki/concepts/secao-hero]], [[wiki/concepts/wireframe]]) ([[wiki/sources/interfaces-web-introducao-workflow-grids-pagemap-wireframes-style-guide]]).

## Para que serve

- **Montar a jornada do usuário** como "um passo a passo" para entender o produto ou serviço, em acordo com os objetivos (slide). Ver [[wiki/concepts/objetivo-da-interface]] ([[wiki/sources/wireframes-parte-1-o-que-e-uso-foco-page-map-papel-e-caneta]]).
- **Não deixar pontas soltas:** algo citado numa dobra precisa ser explicado em outra (mesma fonte).
- **Posicionar os gatilhos** de uma página de vendas. Ver [[wiki/concepts/design-persuasivo]] (mesma fonte).
- **Dar um porquê a cada dobra:** no case do [[wiki/entities/nubank]], Násser foi "definindo primeira dobra, segunda dobra, terceira dobra" em wireframes de baixa fidelidade, "estabelecendo o porquê" de cada uma, para ser "algo proposital" ([[wiki/sources/interfaces-web-introducao-workflow-grids-pagemap-wireframes-style-guide]]).

## De onde vem

1. Do [[wiki/concepts/objetivo-da-interface]]: "você precisa conhecer qual é o objetivo principal para que você construa o flow, o site map, o page map, a interface, os wireframes" ([[wiki/sources/wireframes-parte-2-briefing-objetivo-page-map-leitura-f-z]]).
2. Do levantamento de requisitos: perguntas e respostas com o cliente (o "bate-bola") e o que o designer "pode agregar" para o produto "ser melhor aproveitado na interface" ([[wiki/sources/wireframes-parte-3-passo-a-passo-fidelidade-escala-de-cinza-segredo]]). Ver [[wiki/concepts/requisitos-funcionais-e-nao-funcionais]].
3. Dos [[wiki/concepts/padroes-de-interface|patterns]] do tipo de página, achados por "observação e pesquisa" em sites como o [[wiki/entities/ui-movement]] ([[wiki/sources/wireframes-parte-2-briefing-objetivo-page-map-leitura-f-z]]).
4. Das perguntas que o usuário faz: numa página de venda, "são as perguntas que o usuário faz quando ele está comprando um produto online" (mesma fonte).

## Para onde vai

Na recapitulação da parte 3: requisitos → page map → busca de referências → esboços no papel → [[wiki/concepts/wireframe|wireframes]]. O arquivo de wireframes do curso serve "para vocês construírem bons flows com base nos page maps" ([[wiki/sources/wireframes-parte-3-passo-a-passo-fidelidade-escala-de-cinza-segredo]]). Vem antes de qualquer nível de tela ([[wiki/concepts/fidelidade-de-prototipo]]).

Depois de fixado o page map, escolhe-se da biblioteca "qual wireframe colocar, em qual flow de pagemap você vai encaixar" ([[wiki/sources/interfaces-web-introducao-workflow-grids-pagemap-wireframes-style-guide]]). No [[wiki/concepts/workflow-de-interface-web]], é o primeiro passo dentro dos wireframes (mesma fonte).

A aula prática 1 chama isso de "Frankenstein": "com base no nosso PageMap dá para a gente ir trabalhando e literalmente construindo o seu Frankenstein" ([[wiki/sources/wireframes-pratica-1-hero-page-map-frankenstein-referencias]]):

1. Listar as seções que a página precisa (hero, depoimentos, cadastro...).
2. Para cada uma, puxar um modelo da [[wiki/concepts/biblioteca-de-wireframes]].
3. Juntar tudo "em uma só" página.

## Montar por referências

Em [[wiki/sources/wireframes-pratica-2-page-map-por-referencias-hero-processo-cta]], Násser mostra como chegou ao page map do portfólio dele: comparando sites do mesmo tipo.

1. Salvar sites do mesmo tipo feitos por gente que faz "boas interfaces".
2. Ler o menu fixo, a primeira dobra e as seções em ordem.
3. Ficar com o que se repete entre eles (o [[wiki/concepts/padroes-de-interface|padrão]]) e acrescentar o que o seu caso pede. Ele acrescentou processo e workflow.
4. Passar o page map para o wireframe de baixa fidelidade.

Ao estudar referências, a pergunta é a da ordem das seções: "por que ele colocou nessa ordem [...] o que fica melhor para o usuário nessa ordem" ([[wiki/sources/wireframes-parte-3-passo-a-passo-fidelidade-escala-de-cinza-segredo]]). Saber que wireframe cabe em cada dobra depende de [[wiki/concepts/repertorio]] ([[wiki/sources/interfaces-web-introducao-workflow-grids-pagemap-wireframes-style-guide]]).

## Exemplos das aulas

- **Página de vendas de um curso online:** vídeo de apresentação → diferencial → depoimentos → estrutura do produto → quem dá a aula → bônus → chamada para cadastro ([[wiki/sources/wireframes-parte-1-o-que-e-uso-foco-page-map-papel-e-caneta]]).
- **[[wiki/entities/frontpush]]:** apresentação do produto, detalhes do produto e o CTA "quero me inscrever" repetido pela página. "Eu simplesmente segui isso no page map e montei o meu estilo" ([[wiki/sources/wireframes-parte-2-briefing-objetivo-page-map-leitura-f-z]]).
- **Pricing:** seção de planos em escada (standard ou prata, depois gold) (mesma fonte).
- **Landing page:** ilustração, headline, descrição, botão de call to action, depois empresas ou clientes "para poder causar um pouco mais de autoridade" ([[wiki/sources/wireframes-parte-3-passo-a-passo-fidelidade-escala-de-cinza-segredo]]).
- **Nubank:** primeira, segunda e terceira dobra definidas em baixa fidelidade, cada uma com seu porquê ([[wiki/sources/interfaces-web-introducao-workflow-grids-pagemap-wireframes-style-guide]]).
- **Portfólio:** começa pela seção de hero, que diz "para o que trata o website, qual é o serviço", com "uma headline objetiva e direta, depois um parágrafo mais detalhado abaixo" ([[wiki/sources/wireframes-parte-2-briefing-objetivo-page-map-leitura-f-z]]). O page map completo está na tabela abaixo.

A página da parte 3 diz que a parte 1 da aula de wireframes deu o exemplo de um portfólio ([[wiki/sources/wireframes-parte-3-passo-a-passo-fidelidade-escala-de-cinza-segredo]]). A página da parte 1 registra como exemplo a página de vendas de um curso online ([[wiki/sources/wireframes-parte-1-o-que-e-uso-foco-page-map-papel-e-caneta]]), e o portfólio aparece nas partes 2 e prática 2. As duas páginas não batem nesse ponto.

### O page map do portfólio

Ordem como ele narra ([[wiki/sources/wireframes-pratica-2-page-map-por-referencias-hero-processo-cta]]):

| Seção | O que leva | De onde veio |
|---|---|---|
| Hero | headline "objetiva e direta", parágrafo mais detalhado, ilustrações e branding, botões com CTA | [[wiki/entities/jonas-miller]] (frase de efeito + "solicitar proposta"), [[wiki/entities/fabio-freire]] ("Olá, eu sou...") |
| Processo | como funciona o trabalho; dá autoridade | acréscimo dele |
| Workflow | passo a passo; "ninguém compra ou contrata algo que seja confuso" | acréscimo dele |
| Cases | trabalhos, links, portfólio | os dois |
| Call to action | solicitar proposta, e-mail, mensagem | "solicitar proposta" de Jonas, "get in touch" de Fábio |
| Quem sou eu | foto, um pouco da história; "passa mais realidade" | sobre mim dos dois |
| Redes sociais, novidades, solicitar proposta | links, newsletter, o mesmo CTA de novo | os dois |

Menus das referências: Jonas tem projetos, sobre mim, serviços e orçamento; Fábio tem introdução, sobre mim, trabalhos e contato. Para ele, os dois têm "mais ou menos o mesmo page map". O CTA no hero e no fim sai do objetivo (pedido de proposta); ver [[wiki/concepts/objetivo-da-interface]].

## Page map x sitemap

A aula usa "page map" e "site map" juntos, sem definir a diferença ([[wiki/sources/wireframes-parte-1-o-que-e-uso-foco-page-map-papel-e-caneta]], [[wiki/sources/wireframes-parte-2-briefing-objetivo-page-map-leitura-f-z]]). As versões desta página leram a relação de formas diferentes:

- `[skill: ux-ui-mentor]` **Não é sitemap:** sitemap é a árvore de páginas de um produto (navegação, arquitetura de informação); o page map é a sequência de seções dentro de uma página, mais perto de um roteiro de conteúdo de landing page. Um site de várias páginas teria um sitemap e um page map por página (leitura a partir de [[wiki/sources/wireframes-parte-1-o-que-e-uso-foco-page-map-papel-e-caneta]]).
- Inferência a partir de [[wiki/sources/wireframes-parte-2-briefing-objetivo-page-map-leitura-f-z]]: o site map é a árvore de páginas do site; o page map, a ordem das seções dentro de uma página. `[skill: ux-ui-mentor]` A skill (`references/fluxos-ia.md`) documenta sitemaps como árvore de páginas e separa fluxo de tarefa (passos lineares) de fluxo de usuário (com decisões e erros).
- `[skill: ux-ui-mentor]` **Entre sitemap e wireframe:** é a arquitetura de informação no nível de uma página, o que entra e em que ordem, antes de qualquer visual. Equivale ao "content-first" ou ao "page outline" de outros processos. Fica entre o sitemap (quais páginas existem) e o wireframe (como cada seção se organiza) (leitura a partir de [[wiki/sources/wireframes-pratica-1-hero-page-map-frankenstein-referencias]]).
- `[skill: ux-ui-mentor]` **Equivale ao sitemap:** equivale ao sitemap ou mapa de conteúdo da arquitetura da informação, no nível de uma página; decide hierarquia e sequência antes do layout (leitura a partir de [[wiki/sources/wireframes-parte-3-passo-a-passo-fidelidade-escala-de-cinza-segredo]]).
- `[skill: ux-ui-mentor]` Na skill, o wireframe responde "qual a estrutura?". O page map é essa resposta escrita em lista, antes de qualquer forma na tela. Inferência: num site com várias páginas, o equivalente seria o sitemap; o page map é o mapa de uma página só (leitura a partir de [[wiki/sources/wireframes-pratica-2-page-map-por-referencias-hero-processo-cta]]).
- `[skill: ux-ui-mentor]` A skill documenta **sitemaps**, a árvore de páginas de um produto. O page map é a mesma ideia uma escala abaixo: a estrutura de uma página só, útil em landing pages (leitura a partir de [[wiki/sources/interfaces-web-introducao-workflow-grids-pagemap-wireframes-style-guide]]).

Todas concordam que o page map trata de uma página e o sitemap da árvore de páginas. Divergem no vocabulário: uma diz que page map "não é" sitemap, outra que "equivale" ao sitemap numa escala menor.

## Por que a ordem importa

`[external]` Pela NN/g, a área sem rolar ainda concentra a maior parte do tempo de visualização (57% em 2018), mas as pessoas rolam quando o topo indica que há mais (https://www.nngroup.com/articles/scrolling-and-attention/). Por isso o page map ordena por prioridade e a primeira dobra precisa puxar para a seguinte.

## No projeto Nubank (FrontPUSH, mentoria de UI Design)

Na [[wiki/sources/frontpush-mentoria-ui-design-referencias-patterns-leitura-z-f-contraste|mentoria de UI Design]]: "copiei e colei aqui no Figma, fiquei olhando um para um, um para outro, desenhei um page map e aí sim começou a surgir as ideias". O page map rabiscado vira wireframe de média fidelidade, e uma ideia (o celular virando card) muda no caminho (o cartão girando). Depois dele vem a pergunta de UX: "o que vai ter na primeira dobra, qual é o objetivo da primeira dobra?" ([[wiki/concepts/objetivo-da-interface]], [[wiki/concepts/modelar-referencias]]).
