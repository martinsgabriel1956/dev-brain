# História do Front End

Linha do tempo da web como método de estudo: cada tecnologia de front end existe para resolver o problema da anterior. Segundo [[wiki/entities/fabio-akita]] ([[wiki/sources/historia-do-front-end-akita-ep4]]), entender a sopa de siglas (Sass, Webpack, npm, SPA...) começa por saber **por que** ela existe.

## Cadeia causal

1. [[wiki/concepts/dns]] + TCP/IP + [[wiki/concepts/porta-de-rede|porta]] → servidor web que serve arquivos ([[wiki/concepts/html-hipertexto|HTML]], hipertexto, WWW).
2. [[wiki/concepts/cgi-common-gateway-interface|CGI]] → páginas dinâmicas; PHP/ASP embutem lógica no servidor ([[wiki/concepts/servidor-web-vs-servidor-de-aplicacao]]).
3. Copiar-e-colar de layout → templates e [[wiki/concepts/css|CSS]]; [[wiki/concepts/guerra-dos-navegadores]] fragmenta o suporte.
4. [[wiki/concepts/framework-web|Frameworks server-side]] (Rails) → [[wiki/concepts/biblioteca-javascript-de-compatibilidade|jQuery/Prototype]] contra a incompatibilidade entre navegadores.
5. [[wiki/concepts/ajax]] + [[wiki/entities/gmail|Gmail]] → o navegador vira plataforma de apps.
6. iPhone (2007) mata [[wiki/concepts/plugin-de-navegador|plugins]] e exige [[wiki/concepts/design-responsivo]]; HTML5/CSS3 só oficiais em 2014.
7. Transição caótica 2008–2015 → [[wiki/concepts/transpilador|transpiladores]], [[wiki/concepts/gerenciador-de-pacotes]], [[wiki/concepts/pipeline-de-assets|pipeline de assets]].
8. Estado perto da tela → [[wiki/concepts/single-page-application|SPAs]], componentes, [[wiki/concepts/virtual-dom]]; depois [[wiki/concepts/aplicativo-hibrido|híbridos]].
