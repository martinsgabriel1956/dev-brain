# UI Design

**User Interface Design**: o desenho da forma com que o usuário interage com um dispositivo. Todo dispositivo usado por alguém precisa de software, e o software traz uma interface onde a pessoa entra com dados e recebe resposta. Por isso UI não se limita a sites e apps ([[wiki/sources/o-que-e-ux-ui-design]]).

## O que o UI designer estuda

Segundo [[wiki/sources/o-que-e-ux-ui-design]]:

| Elementos | Princípios |
|---|---|
| Tipografia, ícones, espaçamento entre elementos | Consistência |
| Ilustrações e imagens (como aplicá-las) | Contraste |
| Teoria das cores, formas (o que cada uma comunica) | [[wiki/concepts/hierarquia-visual]] |
| Botões e links | Não cansar o usuário |

As regras servem de direção. Quem domina os princípios pode quebrar algumas.

## Partir do pior cenário

A UI assume que "o usuário sempre vai errar" e usa elementos visuais para guiar a jornada e facilitar decisões ([[wiki/sources/o-que-e-ux-ui-design]]). É a mesma premissa de [[wiki/concepts/usuarios-como-agentes-do-caos]], vista pelo design e não pelo teste. Corresponde à heurística 5 de Nielsen, prevenção de erros `[skill: ux-ui-mentor]`.

## UI como subconjunto de UX

Cada acerto de UI (tipografia, cor, hierarquia, contraste) é pequeno; o acúmulo deles vira "UX dentro do UI". Em teoria de conjuntos, a UI é um dos elementos da [[wiki/concepts/ux-design|UX]] maior, que também cobre empresa e produto ([[wiki/sources/o-que-e-ux-ui-design]]).

`[skill: ux-ui-mentor]` A pirâmide de Aarron Walter (funcional → usável → confortável → prazeroso) dá a ordem: acabamento visual não compensa um fluxo que não funciona.

## Como aprender UI

Roteiro de [[wiki/sources/como-aprender-ui]]: escolher uma ferramenta de prototipagem ([[wiki/entities/figma]] no curso); reproduzir interfaces, copiando sem culpa no início; aprender [[wiki/concepts/porque-das-decisoes-de-design|o porquê de cada decisão]]; seguir boas referências e montar um [[wiki/concepts/mood-board]]; fazer [[wiki/concepts/redesign-como-exercicio|redesigns]] justificados. Contra o bloqueio criativo, a tese é que "criatividade se constrói" com treino ([[wiki/concepts/pratica-deliberada]]).

## O que faz uma boa UI

[[wiki/sources/patterns-o-que-faz-uma-boa-ui-padroes]] não define boa UI pelo positivo; define pelo negativo (contraste mal aplicado, typeface pequena, dashboard lotado) e pelo [[wiki/concepts/objetivo-da-interface|objetivo da interface]]. Uma boa UI cuida de três frentes: apresentar bem a informação, apresentar bem as cores e respeitar os [[wiki/concepts/padroes-de-interface|padrões]] que o usuário já conhece ([[wiki/concepts/lei-de-jakob]]). E "o usuário daquela interface talvez não seja eu".

## Princípios que norteiam a UI

[[wiki/sources/principios-do-design-eixo-simetria-consistencia-simplicidade]] organiza os princípios que as aulas seguintes (grids, ícones, tipografia) vão aplicar: [[wiki/concepts/eixo-visual|eixo]], [[wiki/concepts/simetria-visual|simetria]], [[wiki/concepts/consistencia-visual|consistência]], [[wiki/concepts/contraste|contraste]], [[wiki/concepts/hierarquia-visual|hierarquia]] e [[wiki/concepts/simplicidade-visual|simplicidade]] (com [[wiki/concepts/espaco-em-branco|espaço em branco]]).

## Design de interface: antecipar e facilitar

[[wiki/sources/elementos-da-interface-introducao-ui-design]] define design de interface como "antecipar o que os usuários podem precisar fazer para facilitar a interação" com o produto. Fatores a responder: objetivo, preferências, comportamento, usuário, cultura, posicionamento ([[wiki/concepts/contexto-do-usuario]]). Melhores práticas: simplicidade, consistência, hierarquia, cor e contraste, [[wiki/concepts/feedback-do-sistema]] e patterns. Os [[wiki/concepts/elementos-da-interface]] são o meio de cumpri-las.
