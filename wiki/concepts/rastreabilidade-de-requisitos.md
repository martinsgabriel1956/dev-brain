# Rastreabilidade de requisitos

Ligar cada requisito à tela, fluxo ou funcionalidade que o atende, para que nenhum fique sem solução e nenhuma tela exista sem motivo. Na forma mais simples, é a checklist de [[wiki/entities/nasser|Násser]]: "conforme você for fazendo os fluxos, você olha lá para o seu levantamento de requisito e sai ticando [...] coloca um monte de checkbox lá [...] até você extinguir todo o levantamento de requisitos" ([[wiki/sources/frontpush-dashboards-wireframes-e-fluxos]]).

- **Quando:** entre o [[wiki/concepts/levantamento-de-requisitos]] e os [[wiki/concepts/wireframe|wireframes]]. Ele só passa para wireframe depois de "desenhou todos os fluxos".
- **Os dois sentidos:** requisito sem tela é furo; tela sem requisito é escopo inventado, que vale discutir com o cliente (inferência, alta).
- **Com nomes:** como cada fluxo tem nome ([[wiki/concepts/fluxos-bem-definidos]]), o requisito aponta para o fluxo; no Figma do [[wiki/entities/dash-class|DashClass]], as telas levam "etiquetas" com o fluxo a que pertencem.

Em projetos maiores, vira matriz formal (requisito × caso de uso × tela × teste) e serve também para a validação de aceite.
