# 5 (ou 6) Recursos Para Se Tornar um Desenvolvedor Melhor

## TL;DR

Augusto Galego desafia a recomendação-padrão de LeetCode como melhor uso do tempo e lista seis recursos com retorno maior: documentação oficial do framework, roadmap.sh, CS50, uma seleção crítica de livros (com ressalvas explícitas sobre Clean Code e elogio forte a Refactoring), cursos de Udemy com regra de teto de preço, e contribuição em open source via good first issues. Fecha reforçando que nenhum recurso substitui escrever muito software na prática.

## Key Claims

**Claim:** LeetCode não é o recurso com melhor retorno sobre esforço para melhorar como desenvolvedor.
**Evidence:** Apresentado como a recomendação mais comum que o speaker recebe, mas ele abre o vídeo contestando-a e propondo seis alternativas que, na visão dele, entregam mais retorno antes de chegar em LeetCode.
**Confidence:** média — é opinião do speaker, não dado comparativo

**Claim:** Ler a documentação oficial do framework/runtime usado no dia a dia é o recurso de maior retorno óbvio e mais negligenciado.
**Evidence:** Exemplo concreto: aplicações Node + Express bem construídas exigem entender como o event loop do Node funciona — conhecimento que só vem da documentação, não de atalhos ou tutoriais.
**Confidence:** alta

**Claim:** roadmap.sh resolve o problema de "não sei por onde estudar" oferecendo um mapa ordenado de tópicos por área, mesmo sem ser a fonte mais profunda em cada tópico individual.
**Evidence:** Projeto com 284 mil estrelas no GitHub e mais de 1.000 contribuidores. Para front-end, por exemplo, ordena HTML, CSS, fundamentos de internet/HTTP, layouts responsivos, npm/pnpm, JavaScript e frameworks — cada nó do mapa linka artigos e vídeos de referência.
**Confidence:** alta

**Claim:** CS50 (Harvard) é a alternativa gratuita mais próxima de uma base universitária em fundamentos de CS para quem não cursou faculdade.
**Evidence:** Recomendado explicitamente para esse público, como forma de preencher a lacuna de fundamentos (protocolos, conceitos que a faculdade cobriria) sem custo.
**Confidence:** alta

**Claim:** A avaliação de livros técnicos deve considerar custo-benefício, não só qualidade de conteúdo — um livro excelente mas caro ou inacessível não compensa a recomendação.
**Evidence:** O speaker cita preços da Amazon ao vivo (Cracking the Coding Interview ~R$269, Pragmatic Programmer ~R$428, Refactoring ~R$10) e usa isso como critério explícito de recomendação, elogiando "Arquitetura de Software: As Partes Difíceis" em parte pelo preço frente ao conteúdo denso e difícil de achar em outro lugar.
**Confidence:** alta

**Claim:** Nem todo livro popular no meio técnico merece recomendação incondicional — Clean Code é citado com reserva explícita, enquanto Refactoring recebe endosso sem ressalvas.
**Evidence:** Sobre Clean Code: "o autor é bem cancelado e as dicas são mais ou menos metade boa, metade [duvidosa]... se for ler 10 livros não incluiria esse aqui." Sobre Refactoring: "um livro excelente... vale bastante a pena."
**Confidence:** média — julgamento pessoal do speaker, não consenso citado

**Claim:** Cursos pagos têm uma faixa de preço razoável (R$20–30 em promoção na Udemy) e cursos de milhares de reais para aprender uma tecnologia pontual não se justificam.
**Evidence:** Regra explícita: nunca pagar R$5.000–10.000 para aprender algo como Node — esse patamar de investimento só faz sentido para algo como faculdade. Cita Maximilian Schwarzmüller como instrutor de referência na Udemy.
**Confidence:** alta

**Claim:** Aprendizado multimodal (curso + documentação + projeto prático simultâneos) melhora a absorção em relação a uma fonte só.
**Evidence:** Afirmação pessoal do speaker sobre seu próprio processo, sem estudo citado como evidência.
**Confidence:** baixa — anedota pessoal

**Claim:** Contribuir com open source é mais efetivo quando aplicado a ferramentas que a pessoa já usa no dia a dia, e "good first issue"/"good first fix" são o ponto de entrada padrão no GitHub.
**Evidence:** Exemplo pessoal: o speaker usa Excalidraw nos próprios vídeos e conhece um bug específico (Ctrl+Z ao colar imagem) que poderia reportar, mas ainda não abriu a issue. Também cita ter criado um projeto próprio (roadmap de investimentos) inspirado na estrutura do roadmap.sh, como forma alternativa de se inspirar em open source sem contribuir diretamente.
**Confidence:** alta

**Claim:** Nenhum recurso de estudo substitui a prática de escrever muito código.
**Evidence:** Frase de fechamento do vídeo antes das recomendações finais: ler documentação e fazer cursos não substitui ficar bom escrevendo software na prática.
**Confidence:** alta
