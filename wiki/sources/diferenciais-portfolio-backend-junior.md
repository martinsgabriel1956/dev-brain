# Diferenciais de Portfólio para Dev Backend Júnior

## TL;DR

Para a primeira vaga de backend, o diferencial não é arquitetura sofisticada — é profissionalismo nas bases: testes reais, Docker funcional, SQL além do CRUD, documentação de API, error handling estruturado e observabilidade básica.

## Claims principais

**Claim:** Uma aplicação bem testada é mais valiosa que uma com arquitetura impecável sem testes.
- **Evidência:** 600+ testes de integração numa aplicação pequena em produção demonstra mais confiança que DDD sem cobertura.
- **Confiança:** Alta

**Claim:** Mockar banco de dados em testes é perigoso — usar banco dedicado real para testes.
- **Evidência:** Mock de banco mascara bugs reais; banco de teste dedicado garante que as queries funcionam de verdade.
- **Confiança:** Alta

**Claim:** Deploy em cloud real (AWS, Hetzner, GCP) diferencia mais que deploy em Render/Heroku.
- **Evidência:** Configurar ambiente manualmente demonstra domínio de infra; plataformas one-click escondem a complexidade.
- **Confiança:** Alta

**Claim:** Documentação Swagger/Scalar é rara — 1 em 10 devs se preocupa com isso.
- **Evidência:** Argumento de experiência do autor como recrutador/tech lead.
- **Confiança:** Média (anedótica)

**Claim:** DDD, microsserviços, NoSQL e múltiplos frameworks são desperdício de tempo para primeira vaga.
- **Evidência:** Projetos grandes em produção usam estrutura de pastas simples com os fundamentos acima bem feitos.
- **Confiança:** Alta
