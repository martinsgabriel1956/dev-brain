# BDD — Behavior-Driven Development

## TL;DR

Extensão do TDD que usa linguagem de domínio (Gherkin) para specs executáveis — simultaneamente documentação e testes. Elimina o gap entre o que o negócio especifica e o que o time implementa. Armadilha: BDD sem engajamento do negócio vira apenas testes com sintaxe mais verbosa.

## Claims Principais

| Claim | Confiança |
|---|---|
| BDD não substitui TDD — são complementares | Alta |
| BDD sem PO/QA escrevendo os .feature files = complexidade sem benefício | Alta |
| Specs Gherkin são living documentation — sempre sincronizadas com o código | Alta |
| Overhead de BDD não compensa em times pequenos (2-3 devs) | Alta |
