# User Stories

## TL;DR

User Stories são a unidade mínima de valor entregável em contextos ágeis. Formato: "Como [persona], quero [ação] para [benefício]." Critérios de aceitação em Given/When/Then. Derivadas do PRD, complementam o FRD. O formato força o time a pensar em valor antes de solução.

## Key Claims

- **Foco no usuário antes da solução:** "Como [persona], quero [ação] para [benefício]" — não prescreve implementação. [[wiki/concepts/user-stories]]
- **Given/When/Then (Gherkin):** critérios de aceitação testáveis e objetivos — base para BDD
- **Definition of Ready:** persona clara, critérios escritos, estimada, dependências mapeadas
- **Definition of Done:** código revisado, testes passando, critérios validados por QA/PO, docs atualizadas
- **Three Amigos:** PO + dev + QA escrevem juntos — requer maturidade do time
- **Não substitui spec em sistemas regulados:** integrações críticas com SLA contratual precisam de [[wiki/concepts/frd-functional-requirements-document]]
- **Features de infra pura:** usar tasks técnicas, não user stories
