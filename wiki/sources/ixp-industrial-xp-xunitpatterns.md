# IXP - Industrial XP (xUnitPatterns.com — Gerard Meszaros)

## TL;DR

Verbete curtíssimo da seção "References" do xUnitPatterns.com que finalmente dá corpo próprio ao termo **Industrial XP (IXP)**, até agora só citado de passagem em [[wiki/sources/storytest-driven-development-xunitpatterns]] como o contexto em que Joshua Kerievsky cunhou "storytest-driven development". Define IXP como uma variante "de marca" (branded) do [[wiki/concepts/extreme-programming|eXtreme Programming]], criada por Kerievsky, que acrescenta práticas necessárias para escalar XP para empresas maiores — cita nominalmente apenas uma: **Project Chartering**. Fecha, com fonte primária dedicada, a lacuna deixada em aberto na ingestão anterior ("Joshua Kerievsky e Industrial XP não têm página própria na wiki").

## Key Claims

### 1. IXP é XP + práticas de escala corporativa, não um método concorrente
A fonte é explícita ao classificar IXP como "variante de marca" do XP clássico — não uma metodologia à parte, mas o mesmo corpo de práticas de [[wiki/concepts/extreme-programming]] com adições pensadas para "larger enterprises". Isso alinha com o que [[wiki/concepts/storytest-driven-development]] já registrava (IXP como "variação prática do XP clássico"), agora com confirmação direta em vez de inferência.

### 2. Project Chartering é a única prática de IXP citada nominalmente no glossário
O verbete não define Project Chartering — apenas o nomeia como exemplo do tipo de prática que IXP acrescenta (presumivelmente, algo como definição formal de escopo/patrocínio de projeto antes do trabalho começar, mas isso é inferência externa, não afirmação da fonte). Fica como lacuna: nenhuma outra fonte da wiki define Project Chartering.

### 3. Confirma a autoria de Kerievsky já registrada por contraste
[[wiki/sources/storytest-driven-development-xunitpatterns]] já atribuía a Kerievsky a cunhagem de "storytest-driven development" via IXP; este verbete confirma, de fonte primária dedicada e independente, que IXP é de fato metodologia de Kerievsky — fechando o círculo de atribuição.
