# Como Trabalhar com Projeto Caótico sem Surtar (André Casciotti)

## TL;DR

[[wiki/entities/andre-casciotti]] argumenta que estresse e vontade de "vender coco na praia" são [[wiki/concepts/risco-ocupacional-do-dev]]: criar software ficou fácil (IA), mas mantê-lo em produção cai nos devs, que viram o funil de atrasos, custo e bugs. Em vez de terapia genérica, dá três mantras: (1) [[wiki/concepts/foco-no-que-esta-ao-seu-alcance]], (2) [[wiki/concepts/melhor-possivel-com-o-tempo-disponivel]] (com [[wiki/concepts/priorizacao-pelo-negocio]]) e (3) [[wiki/concepts/complexidade-e-organizacao]] (com [[wiki/concepts/poder-da-barra-de-progresso-e-do-check]]). Fecho: reconhecer as sensações (ansiedade, frustração, incapacidade) para proteger a energia mental.

## Key Claims

| Claim | Evidência (no vídeo) | Confiança |
|---|---|---|
| Estresse é risco ocupacional do dev | Analogia com médicos/bombeiros/policiais; software = poder; "tudo esbarra nos devs", volume maior com IA | Média: opinião de 20+ anos de carreira, sem dados |
| Criar software é fácil, mantê-lo em produção não | Lovable/Cursor/Claude Code geram em horas; corporações não deixam software milionário só com agentes | Média: "não é tão comum quanto você imagina" é percepção |
| Devs têm pouca autonomia sobre os problemas dos projetos | Problemas enraizados na cultura/processos; dev na "base da cadeia alimentar"; a bucha sobra para o dev | Média |
| Entender o jogo e os interesses da empresa evita batalhas perdidas | Gerente PMI vs. Agile; gestão quer resultado, tático/operacional cuida do como | Média: exemplo anedótico |
| Reclamar não desopila, aumenta a raiva | Espera concordância; reclamar ao chefe pode custar o emprego | Baixa/média: sem pesquisa citada [external não verificado] |
| Pequenas mudanças no que está ao alcance geram autonomia | 2 h de 8 h para teste unitário, SonarQube/testes na pipeline, documentação; quem resolve mais ganha mais autonomia | Média |
| Mais tempo = mais tempo gasto; sem data não sai do papel | Projeto com 5 meses de análise/arquitetura que termina na correria igual | Média |
| Prioridade vem do negócio, não do dev | Cadastro por script, regra primeiro | Média |
| Complexidade exige organização proporcional | Reunião de amigos vs. casamento; casa bagunçada vs. arrumada | Média: analogias |
| Lista de tarefas dá barra de progresso e check | Alívio de ansiedade e microvitórias | Média: sem evidência empírica citada |

## Perguntas em aberto

- Quanto da tese "tudo esbarra nos devs" se sustenta com agentes autônomos mais maduros? O próprio autor diz não saber `[inferência do autor]`.
- Os mantras são testados só pelo autor ("depois volta aqui e me fala se funcionou"); não há dado. Para sinais clínicos, o autor remete à terapia, fora do escopo técnico.
- Contraponto: o mantra 1 evita frustração, mas [[wiki/concepts/autonomia-de-sugerir-vs-pegar-para-si]] e [[wiki/sources/o-que-faz-um-engenheiro-de-ia-ser-bom-ronald-hulk]] valorizam quem assume problemas além do escopo; ver nota em [[wiki/concepts/foco-no-que-esta-ao-seu-alcance]].
