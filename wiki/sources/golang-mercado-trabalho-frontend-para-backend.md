# Golang e o Mercado de Trabalho: Como Migrar do Frontend para o Backend

## TL;DR

Vídeo de Q&A respondendo um seguidor (John Lee, dev frontend em São Paulo) sobre se Go é uma linguagem sólida ou passageira e como conseguir uma vaga backend vindo do frontend. Argumento central: Go já se estabeleceu em grandes empresas (Mercado Livre, Mercado Pago, Stone) por ser uma linguagem *cloud native*, ao contrário de tecnologias de nicho como Ruby on Rails que nunca escalaram para adoção em massa no Brasil. A estratégia recomendada para quem vem do frontend: entrar como fullstack numa empresa que já usa Go, ganhar experiência prática de nível pleno no backend, e só depois migrar para uma vaga backend pura.

## Key Claims

1. **Go não é passageiro — já tem adoção estabelecida.** Mercado Livre, Mercado Pago e Stone (Brasil) usam Go de forma consolidada, ao contrário do Ruby on Rails, que teve forte influência histórica mas nunca gerou volume relevante de vagas no mercado brasileiro além de algumas consultorias.
2. **Go é uma linguagem "cloud native" por design.** Foi criada para sustentar a infraestrutura em cloud do Google — isso a torna um forte candidato natural para qualquer backend voltado a cloud, da mesma forma que JavaScript foi desenhado para web dinâmica e Swift para macOS.
3. **Filosofias opostas: Go (pragmatismo) vs. Rust (expressividade).** Rust tem muito mais features e permite soluções "clever"; Go tem poucas formas de fazer cada coisa, forçando uma solução pragmática e crua, mas consistente e fácil de manter. Programar em Go pensando como Rust não funciona bem; o inverso funciona, mas não fica ideal.
4. **Estimativa de adoção Go vs. Node (visão do autor, não medição formal):** ~40/60 no mercado geral (Go/Node), ~80/20 nos EUA a favor de Go, mercado europeu mais fragmentado entre tecnologias por diversidade regional.
5. **Vagas júnior em Go são raras — mirar pleno é a estratégia certa.** Ao aprender uma linguagem de nicho relativo como Go, o dev deve construir portfólio de nível pleno e se candidatar a vagas pleno oferecendo trabalhar por salário júnior, em vez de esperar vagas júnior específicas de Go (que existem, mas são poucas).
6. **A ponte fullstack como caminho de entrada.** Frontends que entram como fullstack numa empresa que já usa Go no backend (exemplo da própria empresa do autor: 3 de 4 devs eram frontend puro e passaram a mexer em Go após a contratação) acumulam experiência prática de pleno mesmo sem vaga backend formal — e depois migram para pleno-plus/quase-sênior em outro backend.
7. **Network importa mais que aplicação fria.** É mais fácil migrar de frontend para backend Go através de conexões com quem já trabalha fullstack nessas empresas do que via candidatura direta.

## Open Questions

- Os números de adoção (40/60, 80/20) são estimativas pessoais do autor, sem fonte de dados formal citada — tratar como opinião qualificada, não medição de mercado.
- Não fica claro se a filosofia "Go pragmático vs. Rust expressivo" é consenso da comunidade ou impressão pessoal do autor — vale cross-checar com outras fontes sobre design de linguagem quando disponíveis.
