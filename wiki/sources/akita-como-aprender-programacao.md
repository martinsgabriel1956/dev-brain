# Como Aprender Programação — Fábio Akita

## TL;DR

Não existe atalho. A diferença entre quem aprende e quem não aprende é simples: autodidatas não param quando o procedimento falha — eles investigam o porquê. Copiar código sem objetivo por centenas de horas é mais eficiente do que qualquer curso. Algoritmos e estruturas de dados são a fundação inegociável. Design Patterns só fazem sentido depois de já ter visto os padrões na prática.

## Key Claims

### 1. Dois tipos de iniciantes
Há uma distinção fundamental entre [[wiki/concepts/autodidata|autodidatas]] e pessoas passivas. Autodidatas encaram o procedimento que falhou como um problema a investigar. Pessoas passivas esperam que alguém resolva por elas. Nenhum curso ou livro corrige isso — é uma postura.

### 2. Cursos ensinam o quê, não o porquê
Tutoriais e cursos introdutórios otimizam para satisfação do aluno, não para aprendizado real. Ensinar o *quê* gera sensação de progresso sem criar fundação. É o equivalente a colorir por número: você segue instruções mas não aprende arte.

### 3. Copiar código é treino, não trapaça
A recomendação central: copiar código do GitHub por horas e dias, sem objetivo de produto. A [[wiki/concepts/memoria-muscular|memória muscular]] se forma, padrões começam a surgir naturalmente, e os objetivos emergem do código — não o contrário.

### 4. O objetivo aparece depois
Iniciantes imaginam que precisam ter uma ideia antes de aprender. É o inverso: você copia código, descobre o que é possível fazer, e o objetivo surge sozinho.

### 5. Design Patterns: só depois da prática
[[wiki/concepts/design-patterns|Design Patterns]] fazem sentido quando você já conhece os padrões na prática e só precisa de nomes para eles. Estudar o GoF sem experiência resulta em aplicação errada de todas as ferramentas. [[wiki/entities/christopher-alexander|Christopher Alexander]] foi a inspiração original — patterns emergem da observação, não são impostos.

### 6. Fundação antes de tudo
[[wiki/concepts/algoritmos-e-estruturas-de-dados|Algoritmos e estruturas de dados]] são o que separa amadores de profissionais. Frameworks e linguagens da moda são simples se a fundação for sólida. Sem fundação, você bate num teto rápido.

### 7. Hacker é quem procura a resposta
A definição original de [[wiki/concepts/hacker-mindset|hacker]] é curiosidade ativa — não apenas faz a pergunta, mas procura a resposta. Todo bom programador é um hacker nesse sentido.

### 8. Foco é infraestrutura
[[wiki/concepts/foco-profundo|Foco profundo]] requer isolamento deliberado. Redes sociais são incompatíveis com aprendizado sério. Akita grava vídeos à noite por isso — silêncio total, zero interrupções.

## Questões Abertas

- Akita distingue autodidatas de pessoas passivas como se fosse uma característica estável — mas é possível desenvolver a postura autodidata deliberadamente? Ou ela é formada na infância?
- A recomendação de copiar código sem objetivo funciona igualmente para todos os tipos de learners, ou favorece perfis analíticos?
- Em que ponto copiar código vira crutch e impede o desenvolvimento do pensamento original?
