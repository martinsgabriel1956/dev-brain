# Monetização e Freelancer, aula 04: como conseguir a primeira vaga (FrontPUSH)

## TL;DR

Aula de cerca de 27 min do módulo "Monetização e Freelancer" do [[wiki/entities/frontpush|FrontPUSH]], desenhada no iPad (Procreate, paleta "FrontPUSH 2.0"). [[wiki/entities/nasser|Násser]] (se nomeia duas vezes) organiza a primeira vaga, de dev ou de design, em cinco passos escritos na tela. Segue a [[wiki/sources/frontpush-monetizacao-freelancer-profissional-t-shaped-autoconhecimento-vantagens|aula 03]].

1. **Faça o exercício do T-shaped:** o júnior que se apresenta como "Full Stack UX UI Motion Designer" está "desconexo"; colunas de "muito bom" e "simplesmente bom" ([[wiki/concepts/profissional-t-shaped]], [[wiki/concepts/posicionamento-no-mercado]]).
2. **Ler e estudar o mercado:** escolher um dos três frameworks de SPA (React, Vue, Angular). Ele escolheu [[wiki/entities/react|React]] pela comunidade, que acha e corrige bugs e gera mais vagas; o mesmo argumento vale para o [[wiki/entities/figma|Figma]] no design. E React "nada mais é do que JS", então estudar a linguagem abre React Native e Node ([[wiki/concepts/fundamentos-antes-do-framework]]).
3. **Ler a descrição da vaga:** dev front pede "front do front" (CSS, responsividade, micro-interações, formulários) e "back do front" (requisições, arrays); design pede UX e UI, às vezes juntos como "Product Design". Vaga júnior que pede demais é filtro: "o trabalho de dois pagando por um" ([[wiki/concepts/vaga-junior-vira-pleno]]).
4. **Como demonstrar experiência:** sem emprego anterior, experiência é contar "trazer algo do mundo das ideias para a realidade": por que fez a to-do list, a requisição crua, o blog com CRUD. "Eu fiz porque estava lá na pauta [...] isso não é resposta" ([[wiki/concepts/demonstrar-experiencia-na-primeira-vaga]]).
5. **Alinhamento empresa × você:** a vaga "é um contrato"; perguntar regime de trabalho, como reagem a bug, quem acompanha o júnior ([[wiki/concepts/pesquisar-a-empresa-antes-da-entrevista]]).

Fecho: projetos com "um bom README" no [[wiki/entities/github|GitHub]], com metodologia, decisões e como instalar e rodar; "o que você puder deixar mastigado".

## Key Claims

### Os cinco passos do quadro

Tela do iPad: "Como conseguir a 1ª Vaga?" · Faça o exercício do T-SHAPED · Ler, estudar sobre o mercado · Ler a descrição da vaga · Como demonstrar experiência? · Alinhamento: Empresa × Você.

### 1. Exercício do T-shaped

- Erro: "querem mostrar a maior quantidade de habilidades possível para a empresa para poder impressionar" e põem "descrições demais no seu perfil", como "eu sou Full Stack UX UI Motion Designer". "Você precisaria de muito tempo para poder ficar bom nas três e você é um júnior, então você percebe como está desconexo isso?"
- O exercício: "literalmente sopa de letrinhas", circular o que é "muito bom" e o que "só conhece", duas colunas. Com isso "você vai já se portar [...] de uma maneira melhor para o mercado", porque a empresa pede "um cara de front, com quais tecnologias".
- Na lista do júnior de front entram "o front do front, que é o front mais visual" e "o front mais voltado para o back"; "na maioria das empresas você vai precisar saber desses dois".
- Note a mudança em relação à aula 03, onde ele dizia que o exercício "não adianta" para júnior; aqui é "a primeira coisa" do júnior (ver Precisões).

### 2. Mercado: framework e comunidade

- A vaga de dev front "sempre vai pedir uma tecnologia": "a framework, que vai ajudar a gente a construir páginas dinâmicas". Páginas estáticas "não detêm de funcionalidade", "só têm de HTML e CSS"; dinâmicas "têm rotas, que abrem um produto no e-commerce, [...] que mandam um e-mail, que têm reatividade", a [[wiki/concepts/single-page-application|SPA]].
- No quadro, três tecnologias "mais utilizadas na construção de SPAs": "você tem que escolher uma das três". Por que React e não Vue ou Angular: "muito conta a comunidade, que é literalmente a quantidade de pessoas que existem utilizando [...], produzindo conteúdo"; "a chance de alguém encontrar um bug e corrigir é maior" ([[wiki/concepts/comunidade-tecnica]]).
- Mesmo argumento para o Figma, "já estou falando para UI designer": features, plugins, "Figma Community", "muito material lá dentro de forma gratuita". "Isso é ferramenta, não é o mais importante, mas é interessante a gente considerar."
- React "nada mais é do que JS, que é o ECMAScript, [...] ES6+". Hooks (`useState`, `useEffect`), SPA, build e Webpack são a parte introdutória, "mas quando você abre uma determinada seção de código [...] você continua escrevendo em JavaScript": async/await e promises "são conceitos do próprio JavaScript". Estudar a linguagem leva a React Native e a Node, e facilita a carreira full-stack ([[wiki/concepts/fundamentos-antes-do-framework]]).
- "Eu escolhi o React [...] porque o mercado tem mais gente, se tem mais gente nesse mercado, automaticamente a quantidade de vagas aqui para o React também é maior", "uma análise do mercado".

### 3. Descrição da vaga

- **UI designer** ("eu estou um pouquinho fora"): UX é "a parte de pesquisa, toda a parte estrutural para você tomar as melhores decisões, não somente ir direto para a tela": teste de usabilidade, acessibilidade, teste com usuário, pesquisa, [[wiki/concepts/mood-board]]. Há vagas "que pedem UX e UI, porque não tem como desvencilhar", e vagas de "Product Design".
- **Dev front:** duas vertentes, "o front do front e o back do front". Visual: CSS, responsividade, "implementar aquilo que está no design", micro-interações, loadings, formulários com resposta ao usuário. Back do front: "requisições de API [...] para o back-end", tratar erro, "abrir ela em um array" com os métodos de JavaScript ([[wiki/concepts/metodos-de-array-javascript]]). "Não tem como você escanjar uma vaga de dev front sem saber essas duas."
- **Filtro:** "se a empresa está pedindo muitas coisas que estão além daquilo que um júnior deve ter que fazer, já desconfia essa empresa, às vezes ela está querendo que você faça o trabalho de dois pagando por um" ([[wiki/concepts/vaga-junior-vira-pleno]]). "Da mesma forma que a empresa quer coisas de você, você também tem que querer coisas da empresa."
- **Base do currículo de front júnior:** HTML e CSS, JavaScript e lógica de programação (ou PHP), um framework (React, Vue ou Angular), "noções de banco de dados", soft skills ([[wiki/concepts/mapeamento-de-requisitos-de-vagas]]).

### 4. Demonstrar experiência

- "Finja que eu sou aqui o nosso amigo recrutador, então diga para mim a sua experiência, em trazer algo do mundo das ideias para a realidade. Então, se você não trabalhou em nenhum outro lugar, é isso aqui que eles querem que você diga."
- Explicar a metodologia e a "linha de raciocínio" de cada projeto: to-do list, "um trabalhozinho de array com requisição [...] HTTP, bem cru". "Eu fiz porque estava lá na pauta e eu fui fazendo porque é interessante a gente fazer, isso não é resposta."
- O porquê do front: "nós estamos ali na meiúca", entre o design (o Figma é estático; "qual vai ser o comportamento quando a pessoa colocar o mouse em cima, tirar, clicar") e o back-end (requisição, parâmetros, extrair a lista).
- O blog: não "porque eu vi lá no curso do Násser e fiz a mesma coisa que ele", mas para "demonstrar a estrutura de uma SPA aplicada no mundo real de maneira simples", com o [[wiki/concepts/crud|CRUD]].
- A narrativa modelo: página estática "utilizando o projeto do [[wiki/entities/nubank|Nubank]]" (responsividade) → exercícios de JavaScript (lógica, requisições, arrays) → blog que junta as duas partes. "Você construiu uma narrativa e você me apresentou uma metodologia de por que você fez isso, isso é experiência" ([[wiki/concepts/storytelling-em-entrevista]], [[wiki/concepts/explicar-o-porque-das-decisoes]]).

### 5. Alinhamento e README

- "Entenda que é um contrato da empresa com você": a empresa diz expectativas e cultura; você pergunta "qual é o regime de trabalho, como é que vocês costumam reagir, por exemplo, quando tem um bug, como é que vocês tratam o júnior, tem alguém para poder acompanhar" ([[wiki/concepts/pesquisar-a-empresa-antes-da-entrevista]]).
- "Você tem que fazer projetos com um bom README": metodologia, processo, decisões, "como é que você fez a instalação", o comando para rodar. "O que você puder deixar mastigado [...] vai facilitar demais." Portfólio fica para "as próximas aulas" ([[wiki/concepts/curriculo-vs-portfolio]]).

## Precisões e ressalvas

- **Júnior e o exercício:** na aula 03, "não adianta você ser júnior e cair nesse vídeo"; aqui o júnior deve começar por ele. A conciliação provável: o júnior faz uma versão curta (o que já estudou), não o mapa completo de quem tem caminhada.
- **"Estático = sem funcionalidade"** repete a confusão já registrada na wiki: estático é do servidor (arquivos prontos), não da interação; o build de uma SPA em React é estático. Ver [[wiki/concepts/site-estatico-vs-dinamico]].
- **React e Webpack** `[external]`: a comunidade e o volume de vagas do React seguem os maiores (pesquisas State of JS e Stack Overflow; alta). Mas o Create React App foi descontinuado em 2025, e hoje se começa com Vite ou um framework (Next.js); "o que é Webpack" deixou de ser parte da introdução. JSX também não é JavaScript puro, embora vire JS.
- **"ES6+"** é ECMAScript 2015 e versões seguintes.
- **"Product Design"** costuma ir além de UX + UI (estratégia de produto, métricas); a aula simplifica.
- **"Um contrato"** é metáfora: a entrevista é uma via de mão dupla. Bate com [[wiki/concepts/cacar-a-empresa-nao-a-vaga]].
- `[skill: tech-mentor-leadership]` A skill cobre contratação do lado do entrevistador (`leadership/engineering-hiring.md`: take-home, live coding); o conselho de README e narrativa é o espelho do que o avaliador procura num take-home.
- **Legenda:** "sobra de letrinhas"→sopa, "tudo list"→to-do list (4×), "Redmi"→README (2×), "crude"→CRUD, "EC6"/"S6"→ES6, "View"→Vue (2×), "Nasser"→Násser (2×). Ficaram literais "escanjar", "o que é o digito", "as empresas peçam muita atenção" e "Script 6+".
