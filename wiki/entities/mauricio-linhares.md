# Maurício Linhares

## Quem É

Engenheiro de software brasileiro experiente, atuação predominante em backend. Participa de bate-papos técnicos em português com outros engenheiros seniores.

## Contribuições relevantes para o wiki

Em [[wiki/sources/filosofia-design-software-podcast-eduardo-matos-otavio-santana-mauricio-linhares]], discute *A Philosophy of Software Design* de [[wiki/entities/john-ousterhout]] junto com [[wiki/entities/otavio-santana]]:

- Nomeia change amplification como o primeiro sinal visível de complexidade ao entrar numa base de código nova (ver [[wiki/concepts/sintomas-de-complexidade-ousterhout]]).
- Descreve a prática de linkar um ticket ao código no momento de aceitar uma solução tática, documentando o motivo e o que precisa ser revisto depois (ver [[wiki/concepts/tech-debt-como-ferramenta]]).
- Detalha por que a API de I/O do Java otimiza para configurabilidade em vez de facilidade de uso, e por que o cliente HTTP padrão do Go e a função `file_get_contents` do PHP são exemplos melhores de camadas simples sobre complexidade escondida.
- No debate sobre TDD, usa o teste como "primeiro usuário" do código para validar design no nível de método/classe, mas discorda que teste unitário consiga guiar decisões de arquitetura — ver [[wiki/concepts/tdd]].
- Escolhe o Cap. 15 do livro (comentários) como o trecho mais importante — ver [[wiki/concepts/comentarios-como-ferramenta-de-design]].
