## Transcrição

você clica duas vezes num programa e ele abre Mas entre esse clique e a primeira tela o sistema operacional executou centenas de operações invisíveis Hoje eu vou te mostrar o que realmente acontece por baixo dos panos Antes de entrar nos detalhes precisamos entender o papel do sistema operacional Imagina um prédio comercial Tem várias empresas funcionando ao mesmo tempo cada uma usando salas energia elevador e banheiro O sistema operacional é administrador desse prédio Ele decide quem usa o que quando e garante que ninguém invada o espaço do outro Sem ele cada programa teria que saber falar direto com hardware Cada jogo editor de texto navegador teria que ter código para controlar o disco a placa de vídeo o teclado E ele resolve isso criando uma camada entre o hardware e os programas E a primeira coisa que ele gerencia são os processos Toda vez que você abre um programa o sistema operacional cria um processo Um processo é uma instância de um programa execução Ele tem um número de identificação o PID que é o process tem um estado e tem sua própria área de memória E essa área de memória é isolada navegador não consegue acessar a memória do editor de texto por exemplo Cada processo vive no seu próprio espaço Isso é fundamental para segurança Se um processo travar em geral ele não vai fazer os outros travarem junto E todo processo passa por um ciclo de vida Ele nasce como um novo vai pra fila de pronto quando tá preparado para rodar entra execução quando o processador dá atenção para ele e pode voltar para esperando se precisar de algo como ler um arquivo do disco Mas e se um processo precisa fazer várias coisas ao mesmo tempo por exemplo navegador que precisa renderizar uma página dar play num vídeo e responder ao teclado tudo ao mesmo tempo É para isso que existem as trads Uma tradprocesso dentro de um processo Cada thread tem sua própria pilha de execução mas todas compartilham a mesma memória Criar um novo processo é como abrir uma empresa nova no prédio com sala própria contrato próprio tudo separado Mas criar uma trad usando os mesmos recursos Por isso criar uma trado E a comunicação entre trades é mais rápida porque elas já compartilham a memória Mas isso tem um preço Se duas trades tentam modificar o mesmo estado ao mesmo tempo o resultado pode ser imprevisível E aí que as coisas ficam um pouco perigosas Imagina que a tradurso um e precisa do recurso dois para continuar Ao mesmo tempo a traduris e precisa do recurso um As duas ficam esperando uma pela outra para sempre Nenhuma das duas consegue avançar Isso é o chamado deadlock É como cruzamento onde quatro carros chega ao mesmo tempo e nenhum dá passagem Todo mundo fica parado Para evitar isso o sistema operacional e os programas usam mecanismos de sincronização O mais comum é Miltex que é o Mutual Exclusion Ele funciona como uma chave de porta Quando uma tradica mas gerenciar tudo isso é complicado E quando tem centenas de trads e processos competindo pelo processador alguém precisa decidir quem roda em qual momento E é exatamente para isso que existe o escalonador que é o scheduler O escalonador é o algoritmo que decide qual processo vai rodar por quanto tempo e quando ele precisa sair para dar lugar pro outro O algoritmo mais clássico é o round robin Cada processo ganha uma fatia de tempo igual por exemplo 10 ms depois de rodar esses 10 msos vai pro próximo Ele é justo mas tem um problema Um processo que tá renderizando vídeo vai receber ao mesmo tempo que um processo que tá esperando você digitar algo Então não faz tanto sentido Por isso sistemas reais usam filas de prioridade Processos mais urgentes entram numa fila que é atendida primeiro O sistema pode até mudar a prioridade ao longo do tempo subindo processo que estão esperando há muito tempo para evitar que sejam ignorados para sempre E essa troca de contexto entre processos que é o contex sutch tem um custo O processador precisa salvar tudo que o processo atual estava fazendo e carregar o estado do próximo Isso acontece milhares de vezes por segundo e você nem percebe Mas tem um problema Se o processo tá rodando como que o sistema operacional consegue tomar o controle de volta para fazer a troca ele consegue através das interrupções Uma interrupção é um sinal que para o que o processador tá fazendo e transfere o controle pro sistema operacional Lembra do escalonador que tava dando 10 msundos para cada processo quem avisa que o tempo acabou é um timer do hardware A cada intervalo esse timer dispara uma interrupção O processador para o processo atual e o sistema operacional assume para decidir quem roda em seguida E não é só timer Quando você aperta uma tecla no teclado o hardware gera uma interrupção Quando disco termina de ler um arquivo gera outra Outro exemplo é quando disco termina de ler um arquivo gera outra interrupção O sistema operacional tá constantemente reagindo a esses sinais Sem interrupções o sistema operacional não teria como retomar o controle Um processo por exemplo poderia monopolizar o processador para sempre Agora que o processo tá rodando e o sistema sabe quando trocar ele precisa de espaço para guardar os dados É aí que entra o gerenciamento de memória Cada processo precisa de memória para funcionar as variáveis o código a pilha de execução tudo fica carregado na RAM mas a RAM tem limite Imagina dois processos gravando no endereço sem ao mesmo tempo sem proteção um sobrescreveria o outro Para resolver isso existe a memória virtual Cada processo acha que tem a memória toda para ele Ele vem endereços do zero até o limite mas esses endereços são virtuais e não físicos O sistema operacional mantém uma tabela de tradução que converte endereço virtual para endereço físico Digamos que o processo peça o endereço 100 o sistema operacional traduz para uma posição real na RAM que pode ser completamente diferente E quando a RAM enche o sistema operacional move para disco os pedaços de memória que não estão sendo usados Isso é o chamado swap Isso funciona mas o problema é que o disco é muito mais lento que a RAM Se o sistema começa a usar swap demais tudo fica travado Mais programas ainda precisam salvar os dados Por exemplo abrir arquivos ler documentos gravar configurações E é aí que entra o sistema de arquivos Quando você salva um documento ele não fica certinho no lugar organizado do disco Imagina que o disco é um bloco gigante de zeros e uns Quem cria abstração de pastas nomes e hierarquia é o sistema de arquivos Um arquivo de 12 MB por exemplo pode estar dividido em vários blocos espalhados pelo disco O bloco 47 o 193 o 512 tudo fora de ordem E aí o sistema de arquivos mantém também uma tabela que sabe onde cada pedaço tá Quando você abre o arquivo ele junta os blocos na ordem certa e te entrega o documento inteiro Cada sistema operacional tem seu próprio sistema de arquivos O Linux usa o X4 o Windows usa o NTFS e o Mac usa o APFS Cada um tem seus tradeoffs de performance segurança e funcionalidades E quando você entre aspas deleta um arquivo na maioria dos casos o sistema de arquivo só remove a referência da tabela Os dados continuam lá no disco até serem sobrescritos por outra coisa É por isso que programas de recuperação de dados conseguem recuperar arquivos às vezes Mas até agora cada programa fala direto com o sistema operacional E se todos os programas precisassem implementar código para acessar o disco a tela a rede seria um caos É para isso que existem as chamadas de sistema Quando o programa quer ler um arquivo ele não acessa o disco diretamente ele faz um pedido por kernel O kernel é o núcleo do sistema operacional a parte que tem acesso total ao hardware e tem uma separação clara Os programas rodam em user mode com acesso limitado O kernel roda em kernel mode que é o acesso total Quando o programa chama open para abrir um arquivo por exemplo o processador troca de modo Ele sai do user mode entra no kernel mode o kernel faz toda a operação e volta pro user mode com resultado Essa separação é o que impede que um programa qualquer saia além da memória do outro ou formatando discos sem permissão por exemplo E é por isso que quando o kernel trava tudo vai travar A famosa tela azul do Windows é um exemplo Isso porque o kernel é a fundação Então se ele cai não tem nada embaixo para segurar Cada vez que você abre um programa tudo isso acontece em milissegundos e o sistema operacional fez parecer tudo muito simples mas agora você sabe o que tá acontecendo por baixo dos panos É isso se aprendeu algo com o vídeo se inscreve e deixa um like que ajuda bastante o canal Valeu
