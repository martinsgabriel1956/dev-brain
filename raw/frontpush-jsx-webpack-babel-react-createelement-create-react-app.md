## Componentes tripartidos

A primeira coisa que eu quero que você se lembre é que é imprescindível você entender a estrutura de Single Page Application, saber que a nossa página é inteira feita por componentes, componentes que são tripartidos, ou seja, eu tenho a parte estrutural, que é o HTML, eu tenho a parte de estilo, que é o CSS e eu tenho a parte de lógica, que é o próprio JavaScript.

E esses componentes são renderizados, tudo é o JavaScript quem faz, então, meio que eu insiro o HTML dentro do JavaScript, eu insiro o CSS dentro do JavaScript, ele que vai renderizar e vai cuspir para mim nessa página em SPA, porque, afinal de contas, é isso que o browser entende, o browser sempre vai entender essas três, o HTML, o CSS e o JavaScript. Então, no final das contas, a gente vai ter esse produto, mas quem renderiza, quem constrói ele tudo é o JavaScript.

## React Element e JSX

Então, vamos lá, o ReactElement, basicamente é que todo elemento, toda tag é criada com a função createElement, que é própria do React, mas quando a gente está falando de criar esses componentes utilizando essas funções do React, olha só, essa sintaxe aqui é um pouco mais verbosa e um pouco mais, sei lá, complicada. E o que eles pensaram? Cara, eu posso fazer essa mesma coisa, só que de maneira um pouco mais didática e qual é a maneira mais didática possível? É eu simplesmente continuar trabalhando com o HTML e com o CSS que eu tinha lá anteriormente, então eu sei que agora o meu HTML e o meu CSS vão ser dentro do JavaScript.

Se você está com dúvida, pode olhar nas aulas de JavaScript ES6+, onde você vai ver que o próprio JavaScript já consegue escrever o HTML, já consigo estilizar tudo por ele sem precisar literalmente inserir esses dois, mas a caráter didática é mais fácil eu trabalhar com algo que eu já conheço e o HTML eu já conheço. Então, é mais fácil eu criar, por exemplo, uma função que retorna para mim um HTML do que criar uma função estabelecendo o objeto do React e acessando o createReactElement para poder criar um componente.

Então, basicamente, o JSX é algo que parece muito com o HTML, você vai ver que é a mesmíssima coisa do HTML, eu abro uma tag, coloco a div, coloco um atributo, coloco um valor, coloco um conteúdo dentro da tag e fecho a tag. Isso aqui é uma sintaxe de HTML, do qual eu já conheço, então parece com o HTML, mas não é. Na verdade, isso aqui é o JavaScript, onde ele aproximou muito essa sintaxe para poder eu ter mais didática, para eu entender mais do processo.

Então, basicamente, quem faz isso é o Babel. O Babel é o responsável por transformar esse elemento criado com o JSX, por isso que chama JSX, o X vem de XML, que é o HTML, mais JavaScript, então meio que é a fusão dos dois. Então, ele transforma isso em funções do React, ele pega alguma coisa que, por exemplo, eu conheço, que eu sou mais próximo, como HTML, mas, na realidade, ele está transpilando esse código, ele está transformando esse código em React, que é o createElement e, de fato, criando os elementos, criando as tags.

Então, o JSX é um JavaScript que parece HTML, que imita as tags da HTML e você pode até criar as suas próprias tags e a gente vai ver isso, porém, no fundo, no fundo é JavaScript e, assim, o JavaScript cria os componentes.

## Webpack e Babel

E agora eu vou falar um pouco sobre Webpack e Babel, quais são esses dois conceitos que eles ajudam, vocês já perceberam que eu falei que foi o Babel quem fez isso e aí o que o Webpack faz e o que o Babel faz que interessam tanto para poder ajudar a gente a programar em React?

Primeira coisa, o browser não entende o JavaScript atualizado e não é só o JavaScript, tudo e qualquer recurso novo que é lançado, o browser demora para poder entender aquilo ali, literalmente, pessoal, é em questão de logística, vamos supor que o ECMAScript lançou uma nova sintaxe de JavaScript, por exemplo, lá na época da arrow function não existia essa sintaxe e eles falaram, tem uma forma agora de você declarar uma função, só que tinha uma maneira mais fácil, arrow function, quando ele acabou de lançar esse recurso, o browser ainda não entende o que é uma arrow function, ele vai olhar para aquilo ali e fala assim, não estou entendendo essa sintaxe.

Isso aconteceu, por exemplo, com o CSS Grid, o CSS Grid é um novo recurso do CSS3 que permite a gente programar estilizar o nosso layout em duas dimensões de maneira mais fácil e no começo, quando acabou de lançar esse recurso, os browsers não entendiam o Grid Layout e foi ganhando essa compatibilidade com o passar do tempo e isso se repete com muitas funcionalidades, porque sempre a gente está programando com o JavaScript bem mais atualizado que o do browser.

Então, precisa de alguém meio que pegar aquele código que está bem atualizado e transformar para uma interpretação daquela função, só que de maneira mais antiga para poder eu conseguir uma maior compatibilidade entre os browsers, afinal, não é todo mundo que tem o browser atualizado e além disso, por mais que seja atualizado, não é garantido que ele tenha essa compatibilidade, que ele entenda essa sintaxe. Então, quem faz isso é o Babel, ele vai converter o código em uma versão mais antiga para poder conseguir essa compatibilidade e é comum que os browsers demorem para poder atualizar esses recursos, então está aí outra funcionalidade do Babel.

Agora, vamos falar um pouquinho sobre, por exemplo, as funcionalidades do Webpack, ele ensina ao JavaScript como importar arquivos, CSS, imagens e etc. Você tem que entender que o Babel vai pegar aquele código que está em JavaScript e vai pegar e transformar em um código mais antigo, isso o Babel faz, beleza, mas como eu vou colocar o CSS dentro do JavaScript, como eu vou colocar uma imagem e colocar dentro do JavaScript? Isso aí quem faz é o Babel e outra coisa também é o Live Reload, vocês vão perceber que quando a gente criar a nossa aplicação, quando a gente salvar automaticamente, ele vai perceber que alguma alteração foi feita e vai recompilar, se é que eu posso dizer assim, ele vai salvar e atualizar a nossa página automaticamente.
