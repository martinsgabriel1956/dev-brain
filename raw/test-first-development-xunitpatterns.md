# test-first development

Fonte original: xUnitPatterns.com — Glossário

Um processo de desenvolvimento que exige escrever e automatizar os testes unitários (unit tests) antes que o desenvolvimento das unidades correspondentes seja iniciado. Isso garante que as responsabilidades de cada unidade de software sejam bem compreendidas antes de serem codificadas.

Diferente do test-driven development, o *test-first development* apenas afirma que os testes são escritos antes do código de produção (production code); não implica que o código de produção seja feito para funcionar um teste de cada vez (design emergente / emergent design). O *test-first development* pode ser aplicado tanto no nível de teste unitário (unit test) quanto no de teste de cliente (customer test), dependendo de quais testes escolhemos automatizar.
